# 因子表达式：可选方法论参考（非强制）

> ⚠️ **本插件的设计原则**：**AI 完全自由设计因子表达式**，**不强制使用任何白名单**。
>
> proposer 可基于任何合理的金融直觉、文献启发、跨域灵感自由构造因子。本文件只是**方法论参考**——给 proposer 提供一些**历史上验证有效的范式**作为起步思路，但不构成任何约束。

---

## 一、设计自由原则

1. **完全自由**：proposer 可以构造任何形式的因子——算术组合、滚动统计、截面运算、时序序列、甚至 LLM 灵感、跨域类比（物理学 / 生物学 / 心理学）。
2. **不禁止任何算子**：只要因子定义清晰、可向量化、计算可行，即可。
3. **不禁止任何数据源**：行情、财务、衍生指标（自构造）、甚至是几个字段的组合衍生。
4. **不禁止重复造轮子**：可以基于白名单变形，也可以从头构造全新因子。
5. **鼓励跨域与新颖**：本插件的核心价值之一就是**比传统白名单更敢试**——只要背后有清晰的金融直觉或可解释的逻辑。

> **唯一的硬约束**：proposer 必须在 `factor_proposal.md` 中给出**清晰的可执行定义**（公式 + 数据依赖 + 计算步骤 + 预期方向 + 可行性自查），否则会被驳回。

---

## 二、可行性自查（proposer 必填，必通过）

proposer 在 `factor_proposal.md` 必须完成以下**可行性自查清单**，任一项未通过 → 主会话**驳回**并要求重提（不是简单的 G-PR FAIL，而是直接重新 propose）。

### F-1. 数据可用性

- [ ] 因子公式中**每一个**字段都在 `templates/data_catalog.md` 中标注为 `available` 或 `derive`
- [ ] 没有 `missing` 字段（否则应改方向或降级）
- [ ] 字段名拼写正确（与 data_catalog 一致）

### F-2. 未来函数风险

- [ ] **未**用到 T 日之后的数据（如 T+1 才发布的财务数据）
- [ ] **未**用到 `end_date`（报告期）—— 必须用 `info_publ_date`（披露日）
- [ ] **未**在滚动窗口中漏掉 `shift(1)`（防"今日用今日数据"）
- [ ] **未**用 T+1 ~ T+H 的收益来"教"因子（这是 leakage）

### F-3. 计算复杂度

- [ ] 计算复杂度 ≤ O(N×T)（N 股票数、T 时间窗口）
- [ ] 不调用未实现的复杂 ML 模型（如神经网络在线训练）
- [ ] 可在 60 秒内完成完整面板计算（粗估）
- [ ] 不依赖未安装的外部包（如 talib 的稀有函数）

### F-4. 样本量

- [ ] 因子计算所需的最早历史数据 ≤ `data_root` 中数据起始日 + 30 天
- [ ] 调仓频率下至少有 36 个调仓期（3 年月度调仓）做评估
- [ ] 不要求过低频信号（如年频信号需要 10+ 年数据）

### F-5. 因子值域与数值稳定性

- [ ] 因子值域有界或经变换后有界（避免极值）
- [ ] 分母不为零 / 极小（除法运算做了 `+ε` 或 `clip`）
- [ ] `log / sqrt / arcsin` 等函数的输入域合法（> 0）
- [ ] NaN / Inf 处理方案明确（drop / fill / clip）

### F-6. 解释性

- [ ] **预期方向明确**：因子值大 → 未来收益高 还是 低？
- [ ] **经济直觉清晰**：行为金融 / 风险溢价 / 套利逻辑 至少占一个
- [ ] **分类标签**：市场 / 基本面 / 混合 + 趋势 / 反转 / 质量 / 估值 / 波动 / 流动性 / 其他
- [ ] **不是数据挖掘巧合**：明确说明为什么这个因子应该 work，而不是「我试了 50 个，这个看起来最好」

### F-7. 与已入库因子的差异

- [ ] 与 `library/approved/INDEX.md` 中已入库因子**显著不同**（不是同一因子的简单换窗口 / 换权重）
- [ ] 若相关性可能 > 0.7，明确说明变形理由

### F-8. 失败教训回避（**完整读取，**逐条引用）

- [ ] **完整读取** `library/lessons/failure_lessons.md` 全文（**不是摘要，必须逐条 ID 引用**）
- [ ] **完整读取** `library/failures/*.md` 全部档案（每份完整看）
- [ ] 在 proposal 中**逐条引用每一条失败条目的 ID**（如 `f003` / `f007` / `f012`），并说明本因子如何回避
- [ ] **新发现的失败模式**（F-1~F-5 未涵盖的）必须**显式列出**并登记新陷阱编号

### F-9. 已知因子撞库自检（**不能是已知因子**）

- [ ] 主动对照 `templates/methodology.md` 第八章**已知因子撞库清单**（alpha101 / Alphalens / 国内经典 / 学术异象 / LLM 常见）
- [ ] 在 proposal 中**列出 ≥3 个最接近的已知因子**（含 Alpha#X、Alphalens Name、国内经典名、学术异象名），并**逐一说明关键差异**
- [ ] **创新点声明**：本因子的**根本性不同** + 采用了**跨域类比 / 反直觉构造 / 原创组合**的具体证据
- [ ] **若本质就是某个已知因子的变形**：必须给出**极强的理由**（从未在 A 股 / 你的时间段 / 你的数据版本下验证过，且变形带来的差异可能改变 IC 方向）；理由不充分 → 主会话**驳回**
- [ ] **不接受「换窗口」「加权重」「中性化叠加」类纯形式变形**——视为雷同

## 三、可选参考范式（**仅供启发，非强制**）

> 以下是历史上被验证有效的因子构造范式。proposer **可以**借鉴，**也可以完全不用**——本节不是白名单。

### A. 行情价量类

- **动量 / 反转**：`close / close.shift(N) - 1`、跳跃动量（跳过最近 K 天）、EWMA 加权
- **价量相关**：`rolling.corr(close.pct_change, volume.pct_change)`、量价背离
- **资金流**：典型资金流 `(close-low-(high-close))/(high-low)*volume`
- **波动率**：已实现波动、Parkinson、Garman-Klass、上行/下行波动比
- **流动性**：Amihud 非流动性、换手率 z-score、换手率趋势

### B. 财务基本面类（**必须用 info_publ_date**）

- **估值**：EP、BP、SP、DP、PEG
- **盈利质量**：ROE、ROA、毛利率、现金流/净利润
- **成长**：营收 YoY、净利润 YoY、EPS 增速
- **健康度**：资产负债率、流动比率

### C. 截面 / 横截面类

- **截面 rank / 分位**：消除绝对值差异
- **双重排序**：先按市值分组再按目标因子分组（剥离规模影响）
- **行业 / 市值中性化**：OLS 残差法

### D. 复合 / 跨域类

- **多窗口融合**：5/10/20/60 日动量等权或加权
- **时序聚合**：max / min / median / quantile over rolling windows
- **跨域类比**：物理学（相变 / 熵）、生物学（代谢率）、心理学（锚定 / 损失厌恶）等启发式构造
- **LLM 灵感**：直接基于大模型对市场行为的推理构造因子

### E. 机器学习衍生（高阶）

- **遗传编程**（gplearn 风格）：用树形算子搜索因子
- **树模型特征重要性**：LightGBM / XGBoost 的特征贡献派生因子
- **深度学习**：MASTER、AlphaGen 类模型生成的因子
- **强化学习**：AlphaGen RL agent 生成的因子

> ⚠️ **E 类**：本插件首版**不内置** ML 生成逻辑，但 proposer 可在 proposal 中**说明**（由 coder 阶段决定是否实现）。如果 ML 路径不可行，proposer 应主动说明并改用统计 / 规则路径。

## 四、白名单被移除后的对比

| 维度 | 旧设计（白名单强制） | **新设计（自由 + 可行性审查）** |
|------|---------------------|-------------------------------|
| 因子来源 | 必须从白名单组合 / 变形 | **完全自由**——任何合理构造 |
| proposer 自由度 | 受白名单约束 | **不受约束** |
| 审查机制 | 仅 G-PR 文件完整性 | **G-PR-7 可行性闸门**（机器判定 + 人工可驳回） |
| 风险 | proposer 困在白名单里出不来 | proposer 敢试，但**可行性不通过直接驳回** |
| 创新空间 | 局限于已知范式 | **跨域 / 新颖** 鼓励 |

## 五、可行性驳回协议

主会话在 review propose 产物时，若发现：

1. **可行性自查未通过**（任一 F-1 ~ F-8 未勾）→ 主会话**直接驳回**，要求 proposer 重提
2. **可行性自查通过但机器判定不可行**（如 G-PR-7 跑出 FAIL）→ 同上
3. **可行性自查通过且机器通过，但主会话人工判断"这个想法站不住脚"** → 主会话**可以驳回**并说明理由（这正是人工审查的价值）

驳回时主会话记录到 `pending_question`，记 `set-stage propose running` 重跑，但**attempts 计数 +1**（防无限重提）。同一 propose 连续 3 次驳回 → `paused_blocked` 报用户决定。

## 六、proposer 收到的 prompt 摘要（更新）

主会话在派发 proposer 时，prompt 摘要应包含：

```
【设计自由度】因子表达式完全自由，**不强制使用任何白名单**。
你可以构造任何形式的因子——算术组合、滚动统计、截面运算、时序序列、
跨域类比、LLM 灵感。

【可行性自查】你必须在 factor_proposal.md 中**逐项勾选** F-1 ~ F-8 共 8 项
可行性自查清单，任一项缺失或未勾将导致驳回。

【失败教训】已读 failure_lessons.md，摘要：<主会话摘抄>
你必须在自检里**逐条复述**至少 3 条失败教训，说明本因子如何回避。

【输出合同】workspace/{id}/spec/factor_proposal.md：
  1. 因子定义（公式 + 数据依赖 + 计算步骤）
  2. 预期方向 + 经济直觉 + 分类标签
  3. 数据可用性自检（标注 available/derive/missing）
  4. 失败教训回避声明（≥3 条，对应失败库具体条目）
  5. **可行性自查清单 F-1 ~ F-8 全勾**
  6. 与已入库因子的差异声明
```
